# 应用安全审查

根据实际输入、执行边界、数据和部署选择控制。没有 HTTP 服务端时，不能硬套服务端安全头或 CORS；也不能把通用最佳实践直接写成确认漏洞。

## 适用性

产品存在用户输入、远程内容、网络请求、本地高权限操作、存储数据、依赖、密钥、文件或浏览器/WebView 行为时使用。完全静态、本地的产品，应把范围缩小到真实的供应链、输入和权限边界。

## 需要检查的证据

检查依赖清单和锁文件、环境模板、密钥处理、请求处理、验证、序列化、模板、SQL/查询构造、浏览器/WebView 设置、上传/存储路径、HTTP 中间件、IAM/配置和日志。仓库历史、CI 扫描、云端加密/IAM、密钥轮换、披露和设备流程需要在可用时获取对应证据。

## 检查项

### 密钥与依赖

- 在适当源码和配置范围内搜索嵌入凭据，不能暴露其值。仓库历史和 AI 聊天记录只有在实际提供并检查后才能确认，否则为 `UNCONFIRMED`。
- 对可能粘贴进配置或聊天的密钥检查轮换流程，不能仅凭代码断言已经轮换。
- 核对包名、来源、锁文件完整性，以及仿冒包或误装包迹象。安全可用时使用现有依赖扫描，不安装用户未要求的工具。

### 输入与执行边界

- 在可信边界验证和授权，不能只在表单验证。优先使用结构化验证和适合上下文的输出编码，而不是笼统“消毒”。
- 仅在相应接收点存在时，追踪 SQL/查询参数、HTML/DOM 渲染、重定向、Cookie、CSRF 防护、请求伪造、路径处理、反序列化和命令执行。
- 对用户提供的 URL、WebView、iframe 或远程内容，检查协议/主机策略、本地网络和本地文件访问、重定向、导航、JavaScript 桥接、sandbox 标志和凭据共享。只有 sandbox 属性不能证明安全。
- 上传功能适用时，需要类型/内容检查、按需恶意软件扫描、大小限制、安全名称/路径、授权，以及不能执行上传内容的存储。

### 平台与数据保护

- CORS 必须符合真实来源和凭据行为。安全头必须覆盖适用的 HTTP 响应，包括错误响应，同时不能不顾产品实际强行添加。
- 使用实际客户端、服务端和平台证据验证 TLS 与静态加密声明。仓库外的云配置没有记录时保持无法确认。
- 对用户、服务、CI、支持和 AI Agent 应用最小权限。检查生产凭据范围和隔离，不能只凭 sandbox 标签推断隔离有效。
- 审计/安全日志应记录有意义的行为者和操作上下文，同时排除密码、令牌、密钥、银行卡号和不必要的敏感负载。
- 漏洞披露和设备丢失响应需要可获得的流程、凭据撤销和所有权证据；仓库没有相关文件不能证明现实中没有流程。

## 验证边界

不得对外部系统运行利用载荷，也不得通过访问真实密钥来证明其可用。只在授权情况下执行非破坏性的本地测试。区分代码检查、扫描结果、运行时响应检查和外部运营证据。

## 输出

返回包含 `finding_id`、`R-02`、严重程度、状态、置信度、具体风险场景、证据 ID/位置、验证、建议和缺失证据的发现。确认已有控制、未知项和未审查项分开列出。中英文内容和 ID 保持一致。要求文档输出时，成对保存 `readiness-application-security-report.en.md` 和 `readiness-application-security-report.zh-CN.md`，不覆盖已有报告。绝不包含秘密值，绝不修改产品文件。
