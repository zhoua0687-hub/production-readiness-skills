# AI 安全审查

审查真实模型和 Agent 数据流，不能把提示词当成可信代码。只有明确范围和技术证据共同证明没有 AI 能力时，才不要求 AI 控制。

## 适用性

产品存在托管或本地模型、提示模板、模型 API、Agent、工具调用、嵌入/RAG、AI 生成操作或模型计费时使用。仅凭缺少 SDK 名称不能排除，因为 HTTP 集成可能隐藏模型调用。

## 需要检查的证据

追踪用户和检索内容进入提示词、模型请求/响应、工具调用、记忆、日志、评测数据集、供应商/模型配置、预算、配额、重试、降级和批准边界的路径。供应商政策、BAA、区域路由、生产配额和评测结果不可用时需要外部证据。

## 检查项

### 不可信内容与敏感数据

- 所有到达模型的用户可控、检索、邮件、上传或工具产生字段都应视为潜在恶意。检查指令/数据分离，以及模型输出是否能授权操作。
- 针对真实工具和数据边界测试提示词注入防护。不能声称只有系统提示词就能阻止注入。
- 客户、患者、秘密和其他受限数据不能离开批准的网络/供应商路径。检查上下文构造、日志、追踪、缓存、微调和第三方插件，而不只是可见提示词。
- 脱敏和保留必须符合数据协议与监管范围；BAA、数据驻留和删除义务与 R-10 协调。

### 成本、质量与供应商变化

- 每客户和全局模型预算、令牌/请求配额、最大 Agent 步数、超时和失控循环防护必须匹配定价模式与滥用风险。
- 成本告警和支出可见性与 R-07 协调。验证实际执行限制，而不只是仪表盘估算。
- 评测必须覆盖重要任务、失败模式和安全边界，并具有基线，能发现模型、提示词或检索变化后的质量退化。
- 供应商宕机行为必须明确：有界重试、降级功能、后备方案或可行动错误。不能因为存在未使用的后备配置就声称具有韧性。
- 模型弃用和迁移需要版本清单、配置所有权、兼容性评测和经过测试的切换路径。

### 操作与记录

- 不可逆或高影响操作必须在事务边界获得有效人工批准。Agent 能绕过的对话框不是批准控制。
- Agent 凭据和工具必须最小权限，并限定当前用户/租户；具体权限执行与 R-02 协调。
- 提示/输出/工具日志必须支持调试，同时排除禁止保存的数据、限制访问和保留期，并保留足够上下文以调查有害操作。

## 验证边界

不得向外部模型发送真实客户数据、秘密或未授权提示。未经明确批准，不得产生模型费用或执行 Agent 工具。没有实际运行评测、后备测试、预算或供应商设置检查时，必须报告为未验证。

## 输出

返回包含 `finding_id`、`R-05`、严重程度、状态、置信度、结论、具体滥用/数据丢失/成本/操作场景、证据 ID/位置、验证、建议和缺失证据的发现。确认已有控制和未知供应商行为分开。中英文内容和 ID 保持一致。要求文档输出时，成对保存 `readiness-ai-safety-report.en.md` 和 `readiness-ai-safety-report.zh-CN.md`，不覆盖已有报告；不修改提示词、模型、预算或 Agent 状态。
